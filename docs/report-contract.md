# Report contract (v1)

How a project reports its versions to Relyz Pulse. Ready-made reporters exist for Payload (`packages/reporter-payload`) and Craft (spec 0004); any other stack can implement this contract directly.

Source of truth: `packages/report-contract/src/index.ts` in the Pulse repo. Machine-readable: [`report-contract.schema.json`](report-contract.schema.json) (JSON Schema 2020-12).

## Request

The hub calls the project's **production** report endpoint:

```http
GET /api/pulse/report HTTP/1.1
Host: www.example.ch
Authorization: Bearer <token>
Accept: application/json
```

- The URL is whatever is configured as "Report endpoint URL" on the project in Pulse.
- The token is generated by Pulse (project → Reporter → Reveal / Copy). Store it in the project's environment, e.g. `PULSE_TOKEN`.
- HTTPS only. Redirects are not followed.
- Compare the token in constant time.

## Responses

| Status | When                                                                      |
| ------ | ------------------------------------------------------------------------- |
| `200`  | Correct token. Body: report JSON (below). Send `Cache-Control: no-store`. |
| `401`  | Missing or wrong token.                                                   |
| `404`  | Reporter disabled — no token configured in the project.                   |

The hub waits at most 10 seconds.

## Payload

```json
{
  "contractVersion": 1,
  "generatedAt": "2026-10-30T12:00:00.000Z",
  "reporter": { "name": "reporter-payload", "version": "1.0.0" },
  "runtime": { "name": "node", "version": "24.11.1" },
  "platform": { "name": "payload", "version": "3.92.0" },
  "packages": [
    { "ecosystem": "npm", "name": "next", "version": "16.4.2" },
    { "ecosystem": "npm", "name": "payload", "version": "3.92.0" }
  ]
}
```

| Field             | Type                                                           | Notes                                                                                                                                                               |
| ----------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `contractVersion` | `1`                                                            | Required.                                                                                                                                                           |
| `generatedAt`     | ISO 8601 date-time with offset                                 | When this response was produced.                                                                                                                                    |
| `reporter`        | `{ name, version }`                                            | The reporter implementation.                                                                                                                                        |
| `runtime`         | `{ name: "node" \| "php", version }`                           | Version of the **running** process, without a leading `v`.                                                                                                          |
| `platform`        | `{ name: "payload" \| "craft" \| "other", version, edition? }` | CMS/framework. `edition` e.g. Craft `pro`.                                                                                                                          |
| `packages[]`      | `{ ecosystem: "npm" \| "composer", name, version }`            | **Direct runtime dependencies** only (`dependencies` / `require`), with the **installed** version, not the declared range. No dev dependencies, no transitive ones. |

## Versioning

- New optional fields can be added without changing `contractVersion`. Consumers must ignore fields they don't know.
- Anything breaking increments `contractVersion`. The hub rejects versions it doesn't support with a clear error.
